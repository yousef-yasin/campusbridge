# CampusBridge – Document Reader

Standalone Python module that turns lecture files into one structure that other modules can use
(for example `ai/text-to-speech`). It follows the same layout and conventions as
`ai/speech-to-text` and `ai/text-to-speech`.

**Phase 1: content extraction**, without AI: the outline, headings and language come from the
file structure and simple rules. **Phase 2: image descriptions** with a vision model (Gemini),
on request only (`--describe` / `ImageDescriber`). OCR of scanned pages is not done yet.

> **Privacy.** Describing images sends each image, the page/slide title and the text around the
> image to Google (Gemini API). On the free tier Google states that content is used to improve
> its products. Do not use `--describe` on private or sensitive material. Extraction alone
> (phase 1) runs fully on this machine.

| Requirement | Implementation |
|---|---|
| `.docx`, text `.pdf`, `.pptx`, `.xlsx` | `open_document(path)`; type detected from the content, not the extension |
| `.doc`, `.ppt`, `.xls` give a clear "save in the new format" error | `UnsupportedFormatError` |
| One structure: blocks with page/slide/sheet, kind, text, language | `Block` (`kind`: heading, paragraph, list, table, image, notes; `lang`: ar, en, mixed) |
| General info: title, type, page/slide count, image and table counts, outline with start page | `doc.info` (`DocumentInfo`, `OutlineEntry`) |
| Natural reading order, right-to-left for Arabic | `layout.order_boxes()` (columns right to left on Arabic pages/slides) |
| Tables as readable text, row by row with column names | `tables.table_text()` |
| Excel: sheet name, columns, row count; rows on request | `doc.info.sheets`, `doc.rows(sheet, start, count)` |
| PowerPoint speaker notes as a separate block | `kind="notes"` |
| Images saved by content hash, image block in place, tiny images and decorations skipped | `images.ImageStore`, `is_decoration()`, repeated-logo filter |
| Scanned PDF reported as needing OCR | `Page.needs_ocr`, `info.needs_ocr`, `info.ocr_pages` |
| Direct access to one page/slide without processing the whole file | `doc.page(n)` |
| Text ready for the TTS module, page by page | `to_speech_text()` |
| CLI `reader extract FILE --page --outline --json` | `python -m reader extract ...` |
| Phase 2: image category, short and detailed description, text inside the image | `ImageDescriber`, `--describe` |
| Explanation language ar / en / mixed, one shared setting | `CB_EXPLAIN_LANGUAGE`, `explain.py` |
| Native charts in .pptx and .xlsx read from the file, without AI | `charts.py`, `kind="chart"` |

## Installation

Python 3.12 (developed and tested on 3.12.10, Windows).

```bash
cd ai/document-reader
py -3.12 -m venv .venv
.venv\Scripts\activate          # Windows  (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
```

Phase 1 runs locally; no file content is sent anywhere. For phase 2 put a Gemini API key in
`ai/document-reader/.env` as `GEMINI_API_KEY=...` (the file is ignored by git; a
`GEMINI_API_KEY` environment variable takes priority).

## Usage

CLI (run from `ai/document-reader`, with `src` on the path):

```bash
# Windows PowerShell: $env:PYTHONPATH="src"     bash: export PYTHONPATH=src
python -m reader extract ../samples-in/lecture.pptx              # info, outline, every page
python -m reader extract ../samples-in/lecture.pptx --outline    # info and outline only
python -m reader extract ../samples-in/notes.pdf --page 3        # one page, nothing else is read
python -m reader extract ../samples-in/notes.pdf --page 3 --json
python -m reader extract ../samples-in/notes.pdf --speech        # text for text-to-speech
python -m reader extract ../samples-in/grades.xlsx --page "الدرجات" --rows 101:50
python -m reader extract file.docx --no-images                   # list images without saving
```

On error the CLI prints `Error: ...` and exits with code 1.

Python API:

```python
from reader import open_document, to_speech_text

with open_document("lecture.pptx") as doc:
    info = doc.info                      # scans the whole file once (cached)
    print(info.title, info.unit_type, info.unit_count, info.image_count, info.table_count)
    for topic in info.outline:
        print(topic.level, topic.title, topic.unit)
    slide = doc.page(5)                  # reads slide 5 only
    for block in slide.blocks:
        print(block.kind, block.lang, block.text)
    for unit in to_speech_text(doc.pages()):
        print(unit.unit, unit.text)      # one string per slide, ready for ai/text-to-speech

with open_document("grades.xlsx") as book:
    sheet = book.info.sheets[0]          # name, columns, row_count, rtl, hidden
    for row in book.rows(sheet.name, start=1, count=100):
        print(row)                       # {"column name": "value", ...}
```

Errors (all subclasses of `ReaderError`): `InputNotFoundError`, `UnsupportedFormatError`,
`PasswordProtectedError`, `CorruptFileError`, `PageNotFoundError`, `ConfigError`.

## The structure

`Block`

| Field | Meaning |
|---|---|
| `kind` | `heading`, `paragraph`, `list`, `table`, `image`, `notes` |
| `text` | Plain text. Lists: one item per line. Tables: one row per line, `column: value` |
| `lang` | `ar`, `en`, `mixed`, or `null` when there are no letters |
| `unit`, `unit_type` | 1-based page / slide / sheet number and which of the three it is |
| `sheet` | Excel sheet name |
| `level` | Heading level (1 = top) |
| `items` | List items |
| `table` | `{"columns": [...], "rows": [[...]], "total_rows": n}` (`total_rows` for Excel previews) |
| `image` | `{"path", "sha256", "ext", "width", "height", "description": ""}` |

In JSON every block also carries its location: `"page": 3`, `"slide": 3` or `"sheet": "Grades"`.

`DocumentInfo`: `title`, `file_type`, `unit_type`, `unit_count`, `image_count`, `table_count`,
`language`, `outline` (`title`, `unit`, `level`), `needs_ocr`, `ocr_pages`, `sheets` (Excel),
`warnings`.

**Language** is decided per block by counting words in Arabic and Latin script: `mixed` when
the smaller script has at least 10% of the words or at least 3 words, otherwise the larger
one. One English term in a long Arabic paragraph stays `ar`.

## How each format is read

### Word (.docx)
- Order: body paragraphs and tables in document order (content controls included).
- Headings: `Title` and `Heading 1-9` styles (also custom styles based on them, and outline
  levels). If the file has no heading styles at all, short bold lines without final
  punctuation become level-3 headings.
- Lists: numbered or bulleted paragraphs; consecutive items are one `list` block.
- **Pages**: a .docx file does not store page numbers. They come from the page breaks Word
  writes when it saves (`lastRenderedPageBreak`), or explicit page breaks if those are missing.
  A file not saved by Word (generated by a program) may report everything as page 1, with a
  warning. Page numbers can differ slightly from what Word shows on another computer.
- Images in the body; images in headers/footers (logos) are not read.
- A one-cell table (a framed call-out box) is read as paragraphs, one per line, not as a table.

### PDF
- Text blocks in reading order. Columns are detected from empty vertical strips and read right
  to left on Arabic pages. Lines that MuPDF splits into bidi runs are joined in logical order.
- Arabic presentation forms (ﻣﻘﺪﻣﺔ) are converted to normal letters (مقدمة). Lines stored in
  visual (reversed) order are detected and repaired when the PDF uses presentation forms.
- Diacritics: a space the PDF puts before a shadda or tanween is removed ("ومهي ّأة" →
  "ومهيّأة"), and a tanween extracted at the start of a paragraph goes back to its last word.
- A sentence the PDF wrote as one block per line is joined back into one paragraph when the
  lines have the same font size, touch, are aligned on the reading side (right for Arabic) and
  the first line does not end a sentence. Lines with space between them (lists) stay apart.
- Headings: text at least 1.25× the document's body font size (level 1 from 1.6×), or short
  bold lines. The body size is measured once per document from up to 10 pages, so a slide-like
  page with two lines of text is judged like the others and levels are consistent.
- Title: the PDF's title field, unless it is the file name or a tool default ("Microsoft Word -
  ..."); otherwise the main headings of page 1 ("Chapter 1 - Information Security").
- Outline: the PDF bookmarks when the file has them, otherwise the level 1-2 headings.
- Lists: blocks where lines start with bullets or numbers.
- Tables: two detectors are combined. PyMuPDF's layout model (its default) finds tables without
  ruling lines but drops some ruled tables, for example ones with only Arabic text; the ruled
  line detector finds those. Each cell is read with the normal text engine, so Arabic keeps its
  logical order, and the columns of an Arabic table start from the right. A one-cell "table"
  becomes paragraphs. Table text is not repeated as paragraphs. `READER_PDF_TABLES=0` turns
  table detection off (much faster: the layout model costs most of the PDF time).
- **Scanned pages**: a page with fewer than 10 text characters whose images cover at least 30%
  of it is reported as `needs_ocr`; its image is still extracted for phase 2.
- **Backgrounds**: an image covering at least 80% of a page whose text is drawn on top of it is
  the slide design, not content: it is skipped and listed in one warning.
- Warnings when the text cannot be repaired: Arabic that looks garbled (a font without a correct
  character map), and Arabic that looks reversed letter by letter without presentation forms.
  Both need OCR or a better source file.

### PowerPoint (.pptx)
- One unit per slide. The title comes first, then the other shapes in reading order (right to
  left on Arabic slides), groups kept together.
- Title placeholder → `heading` level 1, subtitle → level 2, bulleted body → `list`,
  text boxes → `paragraph`, tables → `table`, pictures → `image`.
- Slides without a title placeholder: the text box with the largest font becomes the title
  when it is at least 1.2× every other text on the slide, or when it is 28 pt or more and the
  rest of the slide is short (cover slides). Slides still without a title are listed in one
  warning.
- Speaker notes → one `notes` block at the end of the slide; notes with no letters (only a
  slide number) are skipped.
- Outline = slide titles; consecutive slides with the same title are one topic.
- A one-cell table is read as paragraphs.
- Footers, slide numbers and dates are skipped. Charts are not read (a warning says so).

### Excel (.xlsx)
- One unit per sheet: a heading (sheet name), the sheet's title row if it has one, a summary
  (row and column counts and column names), and a `table` block with the first 20 rows
  (`READER_XLSX_PREVIEW_ROWS`).
- Header: among the first 10 rows, the first one filled across the table (at least 2 cells and
  60% of the fullest row). Text above it (a merged title like "جدول علامات وهمي – 20 طالباً")
  is the sheet title (`SheetInfo.title`), not the header. Only the header's columns are read,
  so notes placed to the side of the table are ignored.
- Row count: rows with a value in the table's columns, counted once by streaming the sheet.
  Sheets over 50,000 rows get an estimate from the saved sheet size (`SheetInfo.approximate`,
  with a warning).
- `rows(sheet, start, count)` streams more rows; the rest of the sheet is not loaded.
- Formulas give their last saved value. A file written by a program without Excel has no saved
  values: the column is empty and a warning names it.
- Right-to-left sheets and hidden sheets are flagged. Charts and images are counted in a
  warning, not read.

## Phase 2: image descriptions

```bash
python -m reader extract ../samples-in/CLT.pptx --page 16 --describe             # mixed (default)
python -m reader extract ../samples-in/CLT.pptx --describe --explain-lang en --max-images 10
python -m reader extract ../samples-in/CLT.pptx --page 16 --describe --speech --detailed
```

```python
from reader import open_document, ImageDescriber, to_speech_text

with open_document("lecture.pptx") as doc:
    pages = list(doc.pages())
    warnings = ImageDescriber(language="mixed").describe_pages(pages)   # fills image blocks
    for unit in to_speech_text(pages):                                  # detailed_images=True
        print(unit.text)
```

- **Model**: `gemini-3.5-flash-lite` (`READER_VISION_MODEL`). From Google's documentation on
  2026-11-18, the free-tier models that accept images are `gemini-4-hydrogen`,
  `gemini-3.6-flash` and `gemini-3.5-flash-lite` (Gemini 4 Carbon and Argon have no free tier;
  Google recommends Hydrogen or 3.5 Flash-Lite for new projects). On that day Hydrogen and 3.6
  Flash answered most requests with 503 "high demand", so the default is 3.5 Flash-Lite, which
  answered every request (about 10 s per image). Set `READER_VISION_MODEL=gemini-4-hydrogen` to
  try the stronger model. Free-tier rate limits are not published per model; see AI Studio.
- **Server errors**: a 500/503 is retried twice (after 5 s and 10 s); the last try asks for plain
  JSON without the schema, because schema-constrained requests failed more often in testing.
  If the service is still overloaded, that image is marked `undescribed` and the next image is
  tried; the run stops after 3 overloaded images in a row. Running again later describes only the
  images that are not in the cache yet.
- **What is sent**: the image (PNG/JPEG/WEBP as is; other formats converted to PNG, very large
  images scaled to 2048 px), the page/slide title and up to 500 characters of text before and
  after the image, so the description fits the lesson.
- **Per image** the model returns a `category` and fills the image block:

| Category | Extra data in `image` | Read aloud |
|---|---|---|
| `table` | `table` (columns, rows) | description, then the rows like any table |
| `chart` | `chart` (type, axes, key values, trend) | description |
| `diagram` | `diagram` (elements, relations in order) | description |
| `equation` | `equation` (written, spoken) | description (how to say it) |
| `text`, `screenshot` | `text` | description, then the text in the image |
| `photo` | `photo` (role in the lesson) | description |
| `decorative` | (none) | skipped |

  The model also answers `informative` (true/false): does the image show information the
  student needs, or does it only set a mood (a person in front of screens, stock photos, title
  slide pictures)? A `photo` with `informative: false` is treated as `decorative`. This was
  added because the same model classified CLT slide 1 as decorative once and as a photo the
  next time: a borderline image, decided by one explicit question instead.

  Every image also gets `description` (one or two sentences), `details` (full explanation),
  `text` (text written inside the image, exactly as written, in its own language), `status`
  (`described`, `needs_review`, `manual`, `decorative`, `undescribed`), `language` and `model`.
- **Number check** (`numbers.py`): the prompt tells the model to copy numbers exactly as written,
  in digits, and never to calculate or round. After each description, every number in the
  explanation (short and detailed description, chart values and trend, diagram, spoken
  equation) is compared by value with the numbers in the image text, the table cells and the
  page text sent with the image; numbers written in Arabic or English words are recognised too
  («أربعة وتسعون» = 94). A number found nowhere there sets `status: needs_review` and
  `unverified_numbers`, is saved in the cache's `number_check`, and gives a warning. Speech then
  drops the sentences with those numbers and reads «الأرقام كما وردت في الصورة: <text in the
  image>». Whole numbers up to 10 are not checked (they usually count what is drawn). Real
  case: in `ar` mode the model wrote 94% for the 95.4% on CLT slide 16.
- **Explanation language** (`CB_EXPLAIN_LANGUAGE` / `--explain-lang`), one setting meant to be
  shared by every CampusBridge AI feature that explains content (images now; the assistant and
  the narrator later), defined in `explain.py`:
  - `ar`: Arabic only, technical terms translated;
  - `en`: English only;
  - `mixed` (default): Arabic explanation; a technical term appears the first time in English
    with its Arabic meaning, e.g. "Central Limit Theorem (نظرية النهاية المركزية)", then in
    English, so students recognise it in the exam.
  Text inside images and table cells is never translated.
- **Cache**: one JSON file per image, model, language and prompt version in
  `image-descriptions/` (`<sha256[:16]>__<model>__<language>__v<N>.json`). It holds the model's
  full answer and a `manual` section: write `manual.short` (and optionally `manual.detailed`) to
  replace the automatic description; it is then read as «صورة: ...» instead of
  «وصف تلقائي: ...». Changing the model, the language or the prompt version gives new entries.
- **Limits**: at most 20 API calls per run (`READER_VISION_MAX_IMAGES` / `--max-images`; cached
  images do not count). Further images are marked `undescribed`.
- **Failures never stop the reader**: no API key, key rejected, quota/rate limit (429; one
  retry if Google asks to wait 30 s or less), no internet, or a format that cannot be sent:
  the image is marked `undescribed` with a `reason`, one warning explains it, and no more calls
  are made in that run after a quota or connection problem. Speech says «صورة بدون وصف».
- **Text-to-speech**: `to_speech_text` reads «وصف تلقائي: <short description>»;
  `detailed_images=True` (`--detailed`) reads the detailed description.

### Native charts (no AI)

Charts drawn by PowerPoint or Excel (not pictures of charts) become `chart` blocks with their
data: `chart = {"type", "title", "x_axis", "y_axis", "categories", "series": [{"name",
"values"}]}`, and a readable text ("مخطط أعمدة بعنوان «...»" then one line per series). PowerPoint
charts use the values saved in the file. Excel charts use the values saved in the chart, else
the referenced cells; formulas without saved results are reported (`missing_values` and a
warning). `info.chart_count` counts them.

## Images

- Saved as `extracted-images/<first 16 hex of sha256>.<ext>`: the same image is stored once,
  across documents. `--no-images` / `READER_EXTRACT_IMAGES=0` lists them without saving.
- Skipped as decorations: images smaller than 48 px on a side, longer than 12:1 (separator
  lines), drawn smaller than 20 points in a PDF, or the same picture on at least 60% of the
  pages/slides in a file of 3 or more (logos, backgrounds).
- `doc.info` counts images without writing any file.

## Text for text-to-speech

`to_speech_text(page or pages)` returns one `SpeechUnit(unit, unit_type, text, sheet)` per
page/slide/sheet:

- blocks separated by blank lines (the TTS module splits long text at paragraph breaks);
- headings and list items end with a period so the voice pauses;
- tables start with a short intro ("جدول، عدد صفوفه 2." / "Table with 2 rows.") then one
  sentence per row; a header-only table is read without the intro (never "0 rows");
- notes start with "ملاحظات المحاضر:" / "Speaker notes:" (`include_notes=False` drops them);
- images: skipped until described; then «وصف تلقائي: ...» (automatic), «صورة: ...» (manual),
  nothing for decorative ones, and «صورة بدون وصف» when the describer could not handle them;
- charts: their summary, one sentence per series.

```python
from reader import open_document, to_speech_text
from tts import Synthesizer            # ai/text-to-speech

with open_document("lecture.pptx") as doc:
    for unit in to_speech_text(doc.pages()):
        Synthesizer().synthesize(unit.text, f"out/slide_{unit.unit}")
```

## PDF library license

PDF reading uses **PyMuPDF, licensed AGPL-3.0** (or a paid commercial license from Artifex).
AGPL requires that if this code runs as part of a network service (the CampusBridge website),
the source code of that service is made available to its users. This must be checked with the
project supervisors before production. All PyMuPDF code is in `pdf_reader.py`, so it can be
replaced (for example by `pypdfium2`, Apache/BSD) without changing the rest of the module.
PyMuPDF was chosen for phase 1 because it gives text positions, bidi-aware Arabic, images and
tables in one library.


Each test builds its own small Word, PowerPoint, Excel and PDF files in Arabic and English, so
no sample files are needed. Phase 2 tests (`tests/test_vision.py`) use a fake vision engine; the
real Gemini client is blocked in tests and the real `.env` is never read. `tests/test_fixes.py` holds one test per problem found on real

not of PDFs saved by Word.

## Limitations

- No OCR of scanned pages yet. Image descriptions come from an AI model and can be wrong,
  especially numbers in charts and small text; important images should be reviewed (the
  `manual` field exists for that).
- Not read: Word text boxes, headers/footers, footnotes and comments, images inside Word
  tables, Word charts; PowerPoint SmartArt text and embedded media; Excel images (counted only).
- Word page numbers are estimates from saved breaks (see above).
- PDF heading and list detection is rule-based; unusual layouts (text in many small boxes,
  rotated text, complex multi-column magazines) may be read in a different order.
- Reversed Arabic can only be repaired when the PDF keeps presentation forms; otherwise, and
  for Arabic with a broken font character map, a warning is given.
- PDF table detection relies on PyMuPDF; a table missed by both detectors is read as
  paragraphs. Which lines a PDF groups into one block is decided by PyMuPDF; wrapped lines are
  joined only in the clear case described above.
- PDF reading is slow with table detection on (about 0.3-0.6 s per page, mostly PyMuPDF's
  layout model), and `info` followed by `pages()` processes the document twice (no page cache
  yet). Reading one page also samples up to 10 pages' text once to measure the body font size.
- A small label above a large title can be merged with it into one heading (PDF).
- Merged table cells are repeated or skipped as the source library reports them.
- Excel: a sheet with several tables side by side or one under another is read as one table.
- Password-protected files are refused (no password option yet).
- Checked on 8 real files (4 Arabic, 4 English: 2 PDF, 2 PowerPoint, 2 Word, 2 Excel); other
  layouts may need new rules.
